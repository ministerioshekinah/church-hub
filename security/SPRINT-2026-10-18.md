## Security findings by severity

| Severity | Finding | Verified evidence / limitation | Recommended action |
| --- | --- | --- | --- |
| High priority | S09 - Administrator revocation | Verified live trigger source silently suppresses ordinary Admin deletion by returning NEW during DELETE. The exact function reproduced a retained account in isolated PostgreSQL; the old API could return success. No production deletion or compromise was tested. | Review the proposed trigger migration and confirmed-deletion Edge handler, stage them, then approve a coordinated backend release. The frontend warning detects the old failure but does not revoke access. |
| High priority | S01 - Database patch level | Verified PostgreSQL 17.6. Supabase announced its 17.11 security rollup on September 25. This is a confirmed patch gap; applicability of individual CVEs and exploitation were not demonstrated. | Schedule a backed-up, staged upgrade review. ltree and btree_gist are absent; pgcrypto is installed. Review legacy cipher/custom-operator compatibility before upgrading. |
| High priority | S02 - Administrator MFA | Verified zero enrolled/verified MFA factors and no AAL2 requirement in application policies. Current access depends on a single sign-in factor. No account compromise was observed. | Build enrollment, challenge and recovery flows, enroll the owner, then enforce AAL2 for CMS writes and the Owner function. Immediate enforcement would risk lockout. |
| Medium | S03 - Leaked passwords | The Supabase security advisor reports leaked-password protection disabled. | Enable it after checking plan support and testing password-change/sign-in behavior. No paid settings were changed. |
| Medium | S04 - Framing protection | Live responses lack CSP frame-ancestors and X-Frame-Options. The meta CSP blocks frames embedded by the site, not embedding of the site by others. This leaves a clickjacking precondition. | Deliver framing restrictions as HTTP response headers through an approved host/proxy. Existing draft PR #14 is a separate, unactivated proposal. |
| Medium | S05 - Public signup | The read-only Auth settings endpoint confirms public signup is enabled despite there being no public registration feature. Tested nonmembers remain denied by RLS. | Move to invitation-only registration after confirming account-management requirements. No production signup, invitation or brute-force test was performed. |
| Medium | S06 - Repository protection | main reports protected=false and no repository rulesets were returned. The scheduled heartbeat job intentionally has contents:write and pushes to main. | Require review and successful checks. Plan how the existing heartbeat operates under protection before changing rules; keep privileged automation narrowly scoped. |
| Low | S07 - Other response headers | HSTS, X-Content-Type-Options and Permissions-Policy are absent on the observed homepage/admin responses. HTTP and www redirect to canonical HTTPS. | Use a staged header rollout. Start HSTS conservatively; do not enable includeSubDomains or preload without checking all subdomains. |
| Low / unconfirmed | S08 - DNS hardening | Apex A and www CNAME match GitHub Pages. No CAA or DS answer was returned. The expected GitHub verification TXT name returned NXDOMAIN; account-level verification status was not available. One nonexistent-host probe also returned NXDOMAIN. | Review domain verification in GitHub, then consider CAA and DNSSEC with the registrar. Missing records alone do not prove an active takeover or compromise. |

Severity is contextual prioritization, not a CVSS score. S01 records an outdated database release, not proof that every upstream CVE is exploitable here. S02 records absent MFA, not evidence of an account takeover. The code defects fixed above affect publishing integrity and reliability; the audit found no demonstrated unauthorized content-write path.

## Fixed security finding

Medium - startup sign-out privacy race. A second tab could retain private unpublished fixture content when it signed out during initial restoration before its auth listener existed. Registering the listener first and invalidating pending responses fixes the reproduced DOM disclosure. This was a local authorized fixture reproduction, not a backend authorization bypass or evidence of production exploitation.

## Reproduce

Use Node 24 or newer and OpenSSL. Browser tests generate an ephemeral local certificate; they do not verify the production certificate.

```sh
npm ci --ignore-scripts
npm test
npx playwright install --with-deps chromium
npm run test:browser
npm audit --audit-level=high
npm audit --prefix security/runtime-dependencies --audit-level=high
```

`npm run test:browser` intercepts all backend requests and never writes to production. Optional `BROWSER_TEST_FILTER` selects named journeys and is recorded in the JSON result. The read-only production and SQL probes are separate, deliberately invoked tools. GitHub runs the complete suite in Chromium, Firefox and WebKit; consult the PR checks and companion CI evidence for the current head. Local follow-up reports identify their selected journeys and timestamps; no build/transpilation step exists for this static site.
