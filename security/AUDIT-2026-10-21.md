## What changed in this follow-up

- Language changes now use short, interruptible opacity fades. Rapid switching starts from the currently displayed opacity and no longer moves the entire reading surface vertically.
- Archive-card hover transforms retain their transition when palette transitions are applied. The hero highlight stays stable instead of repainting a radial gradient on every pointer movement; a subtle opacity glow provides hover feedback.
- Scroll geometry is read before DOM updates, and active-section attributes are only rewritten when the active section changes.
- Closing mobile navigation immediately becomes inert, so keyboard focus cannot enter its links during the closing fade. The desktop breakpoint restores interactivity.
- A cached administrator document clears private editor values, previews, the Owner directory and password fields, then reloads the document so the normal startup verifies current identity and membership before restoring content. Reloading avoids a second authentication flow racing a new sign-in. Tests distinguish synthetic persisted lifecycle events from actual device back/forward-cache behavior.
- New motion and history-security browser checks run through `npm run test:browser`, including the existing three-engine CI matrix.

All existing font files and CSS typography declarations were preserved. Computed families, sizes, weights, line heights and spacing matched the previous branch at 390px/1440px in light/dark mode. The site retains **Inter and Playfair Display**.

## Outstanding work, in priority order

1. **Administrator revocation defect remains live.** The current BEFORE DELETE trigger returns NEW for an ordinary administrator deletion, suppressing that deletion. Deployed `admin-users` v4 does not confirm returned deletion evidence. PR #21 already includes `20261018202726_fix_admin_removal_trigger.sql` and an Edge handler guard, verified with isolated database fixtures. A coordinated approved backend release is required; publishing static files alone cannot apply it. No real account was removed to test this.
2. **PostgreSQL remains 17.6.** The provider's [17.11 security-rollup guidance](https://supabase.com/changelog/postgres-15-19-17-11-breaking-changes) establishes a patch gap. Review the supported upgrade target, backup/restore and extension compatibility before maintenance. Exploitability of individual CVEs was not tested.
3. **Account protections remain incomplete.** Zero verified MFA factors were observed in an aggregate count. Signup remains enabled and [leaked-password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) is disabled. Coordinate MFA enrollment, server-side enforcement, invitation/password setup and recovery before changing these controls, to prevent account lockout. Do not purchase a plan upgrade implicitly.
4. **Firewall/HTTP headers require hosting access.** PR #14 now proposes two disabled, narrowly scoped WAF rules plus six response headers. Their live enforcement is not verified. A GitHub Pages origin remains publicly reachable; a proxy is not an exclusive authentication boundary. The separate proposal documents activation and rollback.

Supabase [network restrictions](https://supabase.com/docs/guides/platform/network-restrictions) cover native database/pooler connections, not HTTPS Auth, REST or Edge requests. The available connector cannot inspect/update those network settings, so their current state is unverified. Website-host WAF rules cannot protect the browser's direct Supabase requests. No administration IP ranges were invented.

Performance Advisor returned five unindexed-foreign-key and three unused-index INFO notices. These were not treated as security vulnerabilities or a reason to drop indexes without workload evidence.

## Verification and limits

Local verification completed: **202/202 Node/database tests**, **65/65 existing Chromium journeys**, **5/5 new motion journeys**, **2/2 history/reload journeys**, **16/16 hosting/WAF contract tests** on the separate hosting branch, and **15/15 read-only live Supabase probes**. Both dependency audits returned zero advisories. The GitHub PR checks are the source of current Firefox/WebKit and final-commit CI status; those engines were not run locally during this follow-up.

Browser checks use an isolated backend with fictional content and accounts. They send no invitations, reset emails or writes to the real site. Motion checks inspect intermediate rendered states, rapid reversals, reduced-motion changes, both themes and mobile-menu keyboard behavior. History tests use real browser PageTransitionEvent handlers and the actual SDK but do not prove physical-device cache/snapshot behavior. Real iPhone/iPad Safari and human assistive-technology review remain outside this execution environment.

The [five-second mobile preview](previews/motion-preview-2026-10-21.mp4) records actual local interactions with fixture content. It is a proposed-change preview, not the deployed website.

This was a bounded defensive review: no password guessing, load test, destructive probe, account mutation or production exploit attempt. See [the earlier operational plan](OPERATIONS-FOLLOW-UP.md) for coordinated backend rollout and rollback requirements.
