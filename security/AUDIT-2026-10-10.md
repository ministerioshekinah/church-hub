# Website security and interaction review — 2026-10-10

Scope: Ministerio Cristiano Shekinah public pages, browser CMS, the admin-users Edge Function, and the four application tables in Supabase. This review was performed with Codex, local automated tests, source/dependency inspection, and live database checks. The separate Codex Security plugin could not be installed and was not used.

`npm test` runs the 81 local tests. `tests/database-security.sql` contains the 21 database checks. `npm run security:live` provides additional read-only HTTP probes and reports hosting/authentication settings separately from passing assertions.

The dependency audits of the pinned Supabase SDKs and frontend test tools reported zero known vulnerabilities at review time. A pattern-based scan of 135 historical Git blobs found no matching private keys, service-role JWTs, or supported secret-token formats. Pattern scans and package advisories cannot prove the absence of unknown vulnerabilities or all secret types.

## Changes

- Explicit content-column queries/grants keep author account identifiers out of browser reads.
- Database triggers stamp content authors and timestamps, preserving creation attribution on authenticated updates.
- Administrator actions require a verified user session and an owner membership from the database; requests are constrained by method, origin, JSON shape, size, email format, UUID format, and role allowlist.
- Internal administrator errors return generic messages; successful handler responses are not cached.
- Public pages gain CSP; the admin SDK has an exact version, verified SHA-384 integrity, and a constrained script source. The admin entry URL redirects without document.write, preserving invitation/recovery parameters on the same origin.
- Optional newsletter section types accept only known own properties; admin HTML attributes are escaped.
- CI runs security and interaction checks, pins action revisions, and isolates the keepalive workflow's repository-write permission to its heartbeat job.
- The public UI gains saved light/dark mode, short bidirectional language transitions, and reduced-motion support. Duplicate newsletter loading and scroll-entry fades are removed; scrolling cards no longer use backdrop blur.

## Remaining account and hosting work

- Disable new public user signups in Supabase Auth if access is invitation-only. Existing RLS rejects CMS writes by users outside the administrator allowlist.
- Enable leaked-password protection if supported by the project's plan. The Supabase Security Advisor reports it disabled.
- Enroll the owner account in MFA. No verified factor was present during the audit; enrollment requires the account holder.
- GitHub Pages does not provide repository-configurable response headers. Full header-based CSP with `frame-ancestors`, HSTS, and `X-Content-Type-Options` requires a suitable host/proxy configuration. Meta CSP does not provide framing protection.

No temporary visitor/password screen is included. Public church content remains public; Supabase Auth/RLS protects CMS actions and unpublished content.

## Limits

These are targeted automated checks, not a guarantee of complete security or an independent penetration-test certification. Edge unit tests mock the authentication wrapper; the live probe script separately checks denial of missing/invalid tokens. Authenticated owner actions were exercised in mocks and rolled-back database transactions; no real user invitation was sent.

Browser/Safari visual and device-performance QA was unavailable in this environment. DOM tests do not measure actual animation smoothness or replace testing on an iPhone. Account settings and hosting headers are listed as follow-up work, not counted as passing tests.
